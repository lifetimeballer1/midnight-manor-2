## Data contract — `data/workplaces.json`

Offsets are logical **tile** offsets from the building centre (`centre = (x + size/2, y + size/2)`,
tile centres at `n + 0.5`). A size-2 footprint centres on a tile corner, so its ring tile centres are
at odd half-offsets; a size-1 footprint centres on its own tile, so ring centres are whole offsets.
Contract: every stand is a walkable tile **outside** the footprint, the target sits **inside** the
footprint at the real job.

| Type | size | stands (offsets) | target | job |
| --- | --- | --- | --- | --- |
| farm | 2 | `(0.5, 1.5)`, `(-1.5, -0.5)` | `(0.0, -0.5)` | crop rows |
| lumber | 1 | `(1.0, 0.0)`, `(-1.0, 1.0)` | `(0.0, 0.0)` | timber felled at the woodlot |

## Simulation API added (`village_sim.gd`)

- `work_position(u: Dictionary, b: Dictionary) -> Vector2` — the worker's reserved stand for its
  workplace, as a tile centre. Reservation is **sticky per unit id** in `stand_slots[workplace_id]`,
  lazily purged when a unit leaves that workplace, so two crew members never trade slots and slots
  survive a save/load. Resolution order: (1) the declared stand for the reserved slot, rotated to the
  next declared stand if that one is blocked **or already held by a crew mate**; (2) any other
  reachable, unreserved ring edge nearest the unit; (3) `Vector2(-1, -1)` = **wait**.
- `job_target(b: Dictionary) -> Vector2` — the data-file job target for a workplace.
- `facing_target(u: Dictionary) -> Vector2` — the recorded work/attack target, else the unit's own
  position (no facing). Used by the renderer only for `work` and `attack`.
- `stand_candidates`, `stand_tile`, `edge_candidates(b, enemy)`, `_walkable`, `_threat_rank`,
  `_threat_enemy`, `_flee_point`, `_archer_space`, `_invalidate` are the supporting helpers.

New per-unit fields: `fx`, `fy` (facing target, `-1.0` = none), `rx`, `ry` (cached retreat goal),
`kite` (bool), `think` (decision countdown). All are primitives/bools, so they survive the existing
versioned JSON save; `_validate_state` now rejects non-finite `fx/fy/rx/ry/think` and a non-bool
`kite` while still accepting older saves that lack them.

`_unit_tick` now walks to `work_position` instead of the nearest arbitrary edge, records the job
target while posted, and — when no stand is reachable — returns without moving, without the `work`
phase, and without touching reserve or carry. Builders face the construction site they are actually
building (`job_target` of that site) and keep their nearest-edge approach. Hauling workers still
deliver to the Manor as before.

`_edge_goal` was refactored onto the shared `edge_candidates` scan with identical ordering and
semantics (nearest reachable edge, then first reachable edge, else wait), so raider pathing is
unchanged. One latent crash was fixed on the way: `edge_candidates` now returns an empty list for a
missing building instead of indexing `{}` (this fires when a world has no Manor Hall).

## Defence

- `_threat_rank` scores each raider `60 / (1 + distance to Manor)` plus `10 / (1 + distance)` for
  every standing non-trap structure; `_threat_enemy` adds a small `-0.35 × distance to the defender`
  term as a tie-break. Manor threats therefore outrank closer structure threats.
- Melee walks its chosen threat. Archers keep their useful range; when a threat closes inside
  **1.5 tiles** they look for a reachable, unblocked tile at least `max(2.4, range × 0.7)` away
  (score `away − steps × 0.35`, at most 3 steps), validated with `route()` before being taken.
  A `kite` flag plus a 0.6 s `think` cooldown gives hysteresis: the archer keeps retreating until
  the gap is safe, then stops and shoots — no oscillation, no retreat into blocked tiles, and no
  retreat at all while `hold` is set.
- Explicit orders and hold are unchanged and still take precedence: a held combat unit fights in
  range without moving, a marching combat unit ignores opportunistic attacks, and neither kites.
- No damage, HP, speed, range or cooldown values were changed. `_nearest_enemy` is still used by
  towers and traps, so structure defence is untouched.

## Caveats and remaining work

- Stand offsets are hand-authored for tier 1 footprints. Tiers do not change footprint size, so the
  same stands hold at every tier, but the visual mesh scale is a factor (up to 1.6) rather than an
  exact tile fit, so stands are correct in tile logic and approximate in pixels.
- Reserve growth means a posted worker picks up goods every ~2 s and walks to the Manor; the tests
  pin reserve to 0 or use arrival-phase polling rather than fixed sleeps for that reason.
- `_auto_assign` re-posts a released worker after ~5 s (existing behaviour); the release test resets
  `job_timer` rather than changing that rule.
- CPU: `NATURAL_RAID_CPU_MS` measured 1034–1058 ms for the existing 100 s simulated wave (headless,
  debug build). No pre-change baseline was captured in this session, so this is an absolute number
  only, not a before/after comparison.
- Headless Godot is not a rendering check. Frame-level smoothness, easing feel and any
  web/mobile performance remain unverified here and still need a desktop pass.
- Out of scope by design and still absent: UI for the new facing data, roads, new resources.
